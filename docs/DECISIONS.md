# Decisions (append-only; change only with the user's approval)
Full derivations are in git history (this file before 2026-09-18's condense) and the matching `docs/PROGRESS.md` log entries.

- D1: Connectome is FlyWire FAFB v783 (Zenodo 10676866 + github.com/flyconnectome/flywire_annotations). Not BANC or MaleCNS.
- D2: Rate model, not spiking. Euler integration.
- D3: Parameters shared per cell type and per (pre type, post type) pair. No per-edge weights.
- D4: Edge signs from predicted neurotransmitter: ACh +1, GABA −1, Glu −1. Others per D11–D13.
- D5: Training is behavior cloning from chart-derived labels. PPO out of scope. ES fine-tuning is a stretch goal.
- D6: Training data is the user's local Clone Hero library (guitar, Easy/Medium/Hard/Expert); the curriculum is the four difficulties. No procedural songs except tiny hand-written test fixtures.
- D7: Out of scope: the real Clone Hero game, screen capture, CGEvents.
- D8: The web viewer plays precomputed replays; no live inference in the browser.
- D9 (default; confirm before Phase 7): the public site hosts no song audio and no chart files; replays show title/artist/charter credit, highway, brain activity, synthesized per-lane hit sounds; optional local-only "load your own audio". **Audio part amended by D37** for the private showcase.
- D10: Shared cross-phase utilities (YAML config loader, run-dir helper) live in `flyhero/utils/` (`config.py`, `run.py`).
- D11: Per-neuron NT sign from `top_nt` (flywire_annotations v3.1.0). Fallback when missing or `top_nt_conf < 0.5`: syn_count-weighted mean of the neuron's outgoing per-edge NT columns, collapsed to one sign per neuron. Counts in `docs/graph_report.md`.
- D12: Photoreceptors (R1–6, R7, R8) forced to histamine, sign −1, regardless of predicted NT. Original predictions in `docs/graph_report.md`.
- D13: Dopamine, serotonin, octopamine all map to sign +1.
- D14: Type-ID fallback chain: `cell_type` → `hemibrain_type` → `cell_class` → singleton. Counts in `docs/graph_report.md`.
- D15: `graph.npz` stores `pos_nm` (4×4×40 nm/voxel) and raw `pos_voxel`, resolved **per neuron**: soma if non-null, else anchor (soma is null for 11,108/11,118 photoreceptors). A per-column version left them NaN; fixed with `test_build_graph_index_round_trip`.
- D16: Gain sharing is `fine` (410,768 g), `coarse` (per (pre_type, post_super_class), 22,212) or `hybrid` (default): a pair keeps its own g if it has ≥ k edges, else the coarse bucket. **k = 2** (93.85% edge coverage; k=3: 85.88%) → 244,824 fine + 18,925 coarse = **263,749 gains**. ES stretch goal uses `coarse`. Answers G1's 410,768 > 300k finding.
- D17: Phase 2 ingest choices (user-approved):
  - Star power ignored and counted in both formats; `sustain_min_beats` (0.5) applies to `.chart` and `.mid`. `duration_s` = `song_length` if > 0, else last note end.
  - >10%-open-notes exclusion is per (song, difficulty). Exact `(artist, title)` duplicates keep the member with most difficulties (then Expert note count, then `rel_path`); near-duplicates are reported in `docs/library_report.md`, never merged.
  - Split is per normalized-duplicate group (stratum `native_easy_medium` if any member has native Easy+Medium). `.mid`: velocity-0 note_on = note_off; tempo from any track. `chart_offset_s`/`ini_delay_s` recorded but unused by rules.py. Real library: 652 candidates, 0 parse failures, 83 open-note exclusions, 5 duplicate drops, 11 near-dup groups, 568 songs, 453/55/60.
- D18: `graph.npz` gained `side_id` (0 left / 1 right / 2 center / 3 na) for the retina's eye split. Metadata only (invariant 3 unaffected); rebuild ~4 s.
- D19: Retina projection (user-approved): no column IDs in v3.1.0, so per-(group, side) PCA 2D projection with anatomically fixed axis signs; medulla chiasm flip calibrated empirically (flip=True, matches anatomy). Mi1 connectivity check median: raw axes 136.7 → PCA 4.95 → L1 spacing reference **1.63** (< 2; 990 columns). The 10 soma-backed photoreceptors get zero current. Both eyes sample the full frame split into halves (confirmed via the user-approved debug video).
- D20: Fret hold = `min(segment_end, t + max(sustain_s, hit_window_s))` (hit_window floor guards frame quantization). `scripted_perfect_actions()` plays these labels exactly; densest Expert val song (Wanderflux): hit_rate 1.000, 0 misses, 0 overstrums.
- D21: G2 env throughput amended ≥10× → **≥5× real time at batch 64 on CPU** (measured 6.8×, naive 0.7×). The brain forward dominates step time anyway.
- D22 (amends invariant 8): song audio may be copied into gitignored `media/` for local use; never committed, never under `web/`. **Extended by D37** for the showcase audio.
- D23: MPS peak memory = polling `torch.mps.driver_allocated_memory()` every substep; CPU = `ru_maxrss`. Not comparable. Both are lifetime/caching high-water marks, so every bench cell runs in its own subprocess.
- D24: gain0 sweep method: "blank highway" = background/lanes/strikeline, no notes; reach/latency threshold 0.01; hard stop if DN reach ≤ 10% or active fraction > 30% across the whole sweep.
- D25 (amends Phase 3's `b = 0` init; still live): **`bias_init = 0.005`** in `configs/brain.yaml`. D12 makes every photoreceptor synapse −1 and photoreceptors are the only externally driven cells, so with `b=0` every other neuron's input is a sum of non-positive terms: 0/128,123 neurons active at any gain0 up to 10,000. A tonic baseline allows disinhibition, as in real fly vision. An initial 0.2 over-saturated `active_frac`. Sweep then passes at **gain0 = 10.0** (active_frac 0.247, DN reach 0.303; chosen) and 30.0 (reach 0.468). User-approved; derivation in `docs/gain0_stability.md`.
- D26: `train/bc.py` memory config **batch=4, no gradient checkpointing**: 4.326 samples/s vs 4.040 (batch 16 + ckpt) and 3.776 (batch 8 + ckpt), all ≤ 40 GiB. G3's batch=8/no-ckpt actually peaks at 47.52 GiB in the real 2 s window (G3's 1 s bench said 24.30). `docs/bench_train_memory.md`.
- D27: Phase 3b training-loop design (user-specified):
  - Note-aware clips: 90% have ≥ 2 notes in the 2 s gradient window, 10% have 0 notes (library median note-free fraction 0.0521). Starts cached in `data/processed/clip_starts/`.
  - Strum `pos_weight` from the sampler's actual positive rate, recomputed on curriculum advance (GRU Medium: 23.44). Decoder: strict ±1-frame local max of strum prob > 0.5, plateau → first frame.
  - Chaos-check threshold < 20% relative DN divergence (measured 3.9%). Curriculum: after passing difficulty N, 20% of clips split evenly over earlier ones (advance rule for `bc` replaced by D36). Checkpoint every 500 steps / 15 min / on SIGTERM.
  - Readout-only: 4,000 cached clips + full-length val DN traces (≤ 10 songs/difficulty). `bc` in-training eval: every 1,000 steps, 10 fixed val songs, fixed 60 s note-dense excerpt. GRU baseline: 3 stride-2 convs (16/32/64) → Linear(128) → GRUCell(128, 256) → shared `Readout`, on the rendered frame (invariant 1 constrains only `ConnectomeBrain`).

- D45 (user decision, 2026-09-21; amends PLAN Phase 6's size budget): **per-song on-disk budget raised 15 MB → 21 MB; the 60 MB total cap is unchanged** (current export: 47.9 MB total, largest song 20.4 MB). Gzipped, the largest song is 10.9 MB vs 20.4 MB raw.

- D49 (2026-09-21; honesty, Phase 7 Session 2): **the brain panel's active-neuron count is "active of 4,096 recorded", not "of 139,241".** The mockup showed "18,402 active of 139,241", but no whole-brain active count was recorded (D44's export ships K=4096 activity slots plus the `scope.bin` scalars), and inferring one from 4,096 slots would be an extrapolation presented as a measurement. - D50 (2026-09-21, Phase 7 Session 3): **the retina is derived in the browser and held to the recording by a parity check, not by assertion.** `web/src/retina.ts` ports `render.py`'s `render_frame`, `retina.py`'s 5-tap sigma-1 blur and nearest-pixel sample, and `sim.py`'s `_obs` (current = `gain * (intensity - ema)` read *before* the EMA update; gain 4.0, alpha 0.2 from `configs/game.yaml`), including Python's half-to-even rounding, which JavaScript does not have. `scripts/check_retina.mjs` (`npm run check:retina`) compares it against `retina.bin` on all three songs: **mean |error| 0.05-0.10 of one uint8 step, worst channel 0.53 steps**, with samples clipped at full scale excluded (export_web.py stores `|current|` scaled by the p99.5 `retina_scale`, so a 255 byte means ">= full scale" and carries no sign). Two conventions the check pins rather than assumes: recorded 60 Hz frame `f` is the highway at song time **(f+1)/60** (record.py consumes the observation after stepping the env) — scored against `f/60`, which is ~90x worse — and `retina.bin` frame k is the mean over frames 3k..3k+2. After a scrub the panel re-seeds the EMA with a **40-frame burn-in**: its memory decays 0.8/frame, so 0.8^40 = 1.3e-4 of any wrong starting state remains, far under the recording's own 1/255 quantization.
