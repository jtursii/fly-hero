# Decisions (append-only; change only with the user's approval)

- D1: Connectome is FlyWire FAFB v783 (Zenodo 10676866 + github.com/flyconnectome/flywire_annotations). Not BANC or MaleCNS.
- D2: Rate model, not spiking. Euler integration.
- D3: Parameters shared per cell type and per (pre type, post type) pair. No per-edge weights.
- D4: Edge signs from predicted neurotransmitter: ACh +1, GABA −1, Glu −1. Others decided in Phase 1 and recorded here.
- D5: Training is behavior cloning from chart-derived labels. PPO is out of scope. ES fine-tuning is a stretch goal.
- D6: Training data is the user's local Clone Hero song library (guitar parts, Easy/Medium/Hard/Expert). The curriculum is the four difficulties. No procedural song generation, except tiny hand-written test fixtures.
- D7: Out of scope: the real Clone Hero game, screen capture, CGEvents.
- D8: The web viewer plays precomputed replays; no live inference in the browser.
- D9 (default; user to confirm before Phase 7): the public site hosts no song audio and no original chart files. Replays show title/artist/charter credit, the highway, and brain activity, with synthesized per-lane hit sounds. A local-only "load your own audio file" option may sync real audio in the browser without uploading or hosting it.
- D10: shared, cross-phase utility code (YAML config loader, run-dir helper) lives in `flyhero/utils/` (`config.py`, `run.py`). Added to the repo layout in PLAN.md during Phase 0 since the original layout diagram had no home for code used by every later package.
- D11: Per-neuron NT sign source (Phase 1) is `top_nt` from the `flywire_annotations` v3.1.0 TSV. Fallback, when `top_nt` is missing or `top_nt_conf < 0.5`: synapse-weighted mean of that neuron's outgoing per-edge NT columns (`gaba_avg`/`ach_avg`/`glut_avg`/`oct_avg`/`ser_avg`/`da_avg`, weighted by `syn_count`) from `proofread_connections_783.feather`, still collapsed to one sign per neuron. Fallback usage counts reported in `docs/graph_report.md`.
- D12: Histamine override — photoreceptor cell types (R1–6, R7, R8; exact `cell_type` spellings confirmed against the live annotations TSV during Phase 1) are forced to histamine, sign −1, regardless of predicted NT. What `top_nt` originally predicted for these neurons is reported in `docs/graph_report.md`.
- D13: Modulatory NTs for v1 — dopamine, serotonin, octopamine all map to sign +1 (not inhibitory). Per-transmitter neuron and edge counts reported in `docs/graph_report.md`.
- D14: Per-neuron type-ID fallback chain (Phase 1 `build_graph.py`): `cell_type` → `hemibrain_type` → `cell_class` → singleton (unique type per unlabeled neuron). Neuron counts landing at each level of the chain reported in `docs/graph_report.md`.
- D15: Neuron positions are stored in `graph.npz` two ways: `pos_nm` (soma/anchor coords converted to nanometers via the FlyWire 4×4×40 nm/voxel scaling) and `pos_voxel` (the raw voxel-index coords as published). Both documented in `docs/graph_report.md` alongside which one is raw vs. derived. Position is resolved **per neuron**, not per column: `soma_x/y/z` is used where non-null, else `pos_x/y/z` (the anchor point) — required because photoreceptor somata sit in the retina, outside the FAFB volume, so `soma_x/y/z` is null for 11,108 of 11,118 photoreceptors (verified in `docs/graph_report.md`). An initial version of `build_graph.py` chose soma-vs-anchor once for the whole column set rather than per neuron, which silently left ~11.1k photoreceptor positions as NaN; fixed before this decision was recorded, with a regression test (`test_build_graph_index_round_trip`).
- D16: Per-(pre_type, post_type) gain sharing is configurable in Phase 3's `brain/rate_model.py`: `fine` (one `g` per realized (pre_type, post_type) pair, 410,768 params), `coarse` (one `g` per (pre_type, post_super_class), 22,212 params), or `hybrid` (default) — a pair keeps its own gain if it has ≥ `k` edges, else it falls back to the coarse `(pre_type, post_super_class)` bucket. `k` defaults to the largest edge-count threshold at which fine pairs still cover ≥ 90% of all edges, chosen from the distribution in `docs/graph_report.md`: **k = 2** (93.85% edge coverage; k = 3 drops to 85.88%), giving 244,824 fine pairs + 18,925 coarse buckets = **263,749 total gain parameters**. The ES fine-tuning stretch goal (Phase 5) uses `coarse` throughout, not `hybrid` or `fine`. This responds to Phase 1's Gate G1 finding that realized type pairs (410,768) exceed PLAN.md's original 300k fallback threshold; the mechanism itself is implemented in Phase 3, not Phase 1 — Phase 1's `graph.npz` already carries the fine-grained `pair_id` plus `type_id`/`super_class_id`, sufficient to derive any of the three schemes without rebuilding the graph.
- D17: Phase 2 ingest (`flyhero/game/ingest.py`) design choices beyond PLAN.md's original task list, approved by the user:
  - Star power (`S`) events in `.chart` are ignored and counted, symmetric with `.mid`'s star-power handling. `sustain_min_beats` (config, default 0.5) applies to both `.chart` and `.mid`, not just `.mid` as PLAN's task 2/3 wording implied.
  - `Song.duration_s` = `song.ini`'s `song_length` (ms→s) when present and > 0, else the last note's (incl. sustain) end time.
  - The >10%-open-notes exclusion (v1 rule simplification) is evaluated and applied **per (song, difficulty)**, not per song — a song's other difficulties survive even if one is dropped.
  - Exact-duplicate `(artist, title)` resolution (raw, case-insensitive, rich-text-stripped match): keep the member with the most surviving difficulties, tie-broken by Expert note count, then by `rel_path`; every drop is logged with both sides' numbers. Near-duplicates (same *normalized* — lowercased, bracket/parenthetical-stripped — key but different raw key) are reported in `docs/library_report.md` for manual review, never auto-merged or dropped.
  - The train/val/test split is assigned **per normalized-duplicate group, not per song_id**: every member of a group (near-duplicates included) lands in the same split, so two charts of the same underlying song can't leak across train/test. Stratum (`native_easy_medium` vs `expert_only`) is per group: `native_easy_medium` if *any* member has both native Easy and Medium surviving the open-note filter.
  - `.mid` parsing: a `note_on` with `velocity=0` is treated as a `note_off` (standard MIDI running-status convention, used by real game-ripped files). The tempo map is built from `set_tempo` messages found in *any* track, not just track 0 (the conductor-track convention), with a warning if one is found elsewhere.
  - `Song` carries `chart_offset_s` (`.chart`'s `Offset`, seconds; 0.0 for `.mid`, which has no such concept) and `ini_delay_s` (`song.ini`'s `delay`, ms→s) — both recorded per PLAN's instruction but unused for training (invariant 4: `game/rules.py` is the only scoring implementation and doesn't read them).
  - Full rationale and real-library numbers (652 candidates, 0 parse failures, 83 open-note exclusions, 5 exact-duplicate drops, 11 near-duplicate groups, 568 songs written, 453/55/60 train/val/test split) in `docs/PROGRESS.md`'s Phase 2 tasks 1-5 log entry.
- D18: `graph.npz` gained a `side_id` array (0=left/1=right/2=center/3=na, from the annotations' `side` column) during Phase 2 tasks 6-11 — metadata, not topology/synapses/signs, so invariant 3 is unaffected, but it's a change to a Phase-1-built artifact, logged here for that reason. Needed because `game/retina.py` must split photoreceptors into left/right eye groups and no per-node side field existed in `graph.npz` as originally built (only an aggregate `photoreceptor_side_counts` report). `graph.npz`/`graph_shuffled.npz` were rebuilt; both takes ~4s from already-downloaded raw data.
- D19: `game/retina.py`'s photoreceptor visual-field projection (Phase 2 task 9), approved by the user with two changes from the original ask:
  - Column/ommatidium IDs are **not available** in the v3.1.0 annotations (checked directly: all 31 header fields, none column-related), so each of the four groups (R1-6 lamina / R7+R8 medulla, × left/right side) gets its own per-group PCA-derived 2D projection (fit once per (group,side) population) rather than a raw-axis (Y,Z) projection — the naive raw-axis version failed a real connectivity check by 70x (see below) because the lamina/medulla are curved, tilted neuropils whose second principal axis is a genuine mix of X and Z, not pure Z.
  - Axis signs are fixed anatomically (dorsal=image top; each PCA component's sign set by correlation with the real Y/Z axis), not PCA's arbitrary sign. The medulla group's front-to-back chiasm-inversion sign is calibrated empirically — tried both orientations, kept whichever minimizes the connectivity-check distance below — rather than assumed from anatomy alone; the empirical result (flip=True) agrees with the expected "front-to-back inverted" anatomy.
  - **Connectivity check** (R1-6→L1→Mi1 and R8→Mi1: cells sharing a Mi1 column should map to nearby image positions): naive raw-axis projection scored 136.7 lattice spacings (median); fixing the projection to per-group PCA got to 4.95; fixing the lattice-spacing reference from R1-6 (contaminated by within-column, neural-superposition-collapsed distances) to L1 (~one cell per column) got to **1.63, under the required <2 threshold**. 990 Mi1 columns tested.
  - The 10 soma-backed photoreceptors (D15; 7 R7, 2 R8, 1 R1-6) are excluded from retina input entirely (zero current), per the user's explicit instruction, rather than rebuilding `graph.npz` with a separate always-anchor position field for them.
  - Both eyes sample the same full `[0,1]²` rendered frame (PLAN's original spec), split into left/right halves with each eye's frontal direction toward the shared midline — one reasonable reading of "each eye's field on its own side of the screen" among a few; flagged for the user to confirm or correct via the debug video.
  - Full numbers in `docs/PROGRESS.md`'s Phase 2 tasks 6-11 log entry.
- D20: `game/labels.py`'s fret-target hold duration is `min(segment_end, time_s + max(sustain_s, hit_window_s))`, not `min(segment_end, time_s + sustain_s)` — the `hit_window_s` floor (approved by the user) guards against frame-quantization rounding a zero-sustain note's own strum frame to just after `time_s`, which the pure-`sustain_s` version could exclude from that note's own target hold in dense passages. `game/rules.py`'s `scripted_perfect_actions()` plays exactly these labels rather than an independently hand-rolled hold window, both because an independent window would OR together on overlapping dense-trill notes (turning hits into overstrums) and because doing so directly validates that the label design is playable — confirmed by a real-data regression test on the densest Expert val song (Aquellex - Wanderflux, 90% of adjacent note gaps under 2×hit_window_s): hit_rate 1.000, 0 misses, 0 overstrums.
